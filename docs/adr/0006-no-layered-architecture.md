# 層状アーキテクチャ(DDD戦術パターン/クリーンアーキテクチャ)は採用しない

このコードベースは、外部サービスごとにモジュールを分けた薄いオーケストレーション構成
(index.ts=ルーティングと分岐、classify/notion/push=外部サービスのアダプタ)とし、
Entity/Repository/ユースケース層・インターフェースによる依存性逆転は意図的に導入しない。
全体で1000行未満・開発者1人・ドメインロジックがほぼ無い「外部API間の仲介」であり、
層を導入して得られるのは「いつか差し替えるかもしれない抽象」だけで、コード量と読解コスト
だけが増えると判断した。

一方、戦略的DDDは採用している: ユビキタス言語はCONTEXT.md、コンテキスト境界は
ADR-0001(全体俯瞰はNotionの領土)、ドメイン原則はADR-0004(タスクを絶対失わない・
誤爆より空振り)として明文化済み。

## 抽象を導入する「引き際」

次のいずれかが起きたら、この決定を見直す:

- **データストアがNotion以外にも増える** → Repositoryインターフェースを切る
- **意図判定後の分岐ルールが複雑化する**(条件が絡み合いユニットテストしたくなる)
  → processTaskから純粋関数のドメイン層を抽出する
- **開発者が2人以上になる** → 層の境界を「会話の共通言語」として整備する価値が生まれる
